# Следующие этапы

Реализовано: схема из 37 таблиц и пять миграций, adapter конфигурируемых
JSON-полей, upsert, исходные snapshots, Celery worker/Beat, HTTP-квота,
lease, сводка, дерево, креативы, фильтры и Action Engine с журналом.
Добавлены bulk actions, свой Rule Engine с DRY_RUN и cooldown, редактор
правил и аудит с причинами. Доступ пока рассчитан на одного локального оператора.
Добавлены математические Winner/Loser/Fatigue Detector с общими порогами
workspace и отдельным экраном рекомендаций без изменения рекламы.
Добавлены AI Copilot, durable approval flow, Autopilot policy и Telegram
approve/review/reject. Внешний AI, Telegram и Autopilot пока выключены;
интеграции проверены на mock HTTP. См. [AI setup](ai-copilot.md).
Добавлены уровни автономности 0–3, общий Emergency Stop, агент с DB tools,
чат Web/Telegram, CONFIRM для естественных команд и постоянные профили GEO/offer.
См. [Agent setup](ai-agent.md).

Осталось для подключения реального аккаунта:

1. Проверить read-ответы: scopes, pagination, поля, историю, текущие
   статусы/бюджеты, родительские связи и атрибуцию. Настроить schema JSON.
2. Проверить на PostgreSQL контейнерный запуск и restore резервной копии.
   Пока миграция исполнялась на SQLite, PostgreSQL DDL компилировался offline.
3. Настроить два ключа, тариф/квоту, профиль загрузки и операторский доступ.
4. Проверить единицы budget и payload, затем включить команды на выбранной
   тестовой сущности. Реальные рекламные команды пока не отправлялись.

Далее: полноценные пользовательские сессии/роли для команды, отдельные
broker/DB grants для изоляции действия, большие таблицы с SQL-агрегатами,
почасовая синхронизация, проверка LLM/Telegram на реальных ключах и прямой MetaConnector.
Bid заблокирован до подтверждения поддерживаемого API/стратегии ставок.

Масштаб синхронизации выбирается по числу кабинетов, объявлений,
глубине истории и тарифу. Интерфейс работает с собственной БД; открытие
страницы не должно запускать запросы провайдера.
